2026-11-02 智能车课程调试记录。今天完成了双轮电机开环验证，并在此基础上恢复编码器速度 PID 控制。

## 1. PID 需求确定

本次控制目标是左右轮独立速度环：

```text
反馈：编码器增量计数
控制输出：左右轮电机 PWM
控制周期：10 ms
目标单位：每 10 ms 编码器脉冲数
控制器：左右轮各一个 PID
停止策略：目标速度为 0 时清除积分并停止
```

编码器映射为：

```text
左轮：TIM5，P10.3 计数，P10.1 方向
右轮：TIM6，P20.3 计数，P20.0 方向
```

第一版参数采用定点缩放：

```c
#define SPEED_CONTROL_KP  (1000)
#define SPEED_CONTROL_KI  (40)
#define SPEED_CONTROL_KD  (0)
#define PID_GAIN_SCALE    (1000)
```

这组参数用于首次上车验证，不代表最终整定结果。

## 2. 先做开环，不直接调 PID

最初直接接入 PID 会把电机、编码器和控制算法的问题混在一起。于是先暂时关闭速度环，只保留按键控制和电机输出，使用 KEY3 进行单轮和双轮测试。

开环测试中出现了几个现象：

1. 上电后右轮异常转动；
2. KEY3 档位与实际转动轮不一致；
3. 左轮方向与预期相反；
4. 右轮在 PID 模式中能够转动，但开环模式表现不一致。

这些现象说明问题不一定在 PID，而可能在电机驱动接口理解和引脚映射。

## 3. 从“方向+PWM”修正为 A/B H 桥

最初把四个端口理解为两组“方向+PWM”：

```text
P02.4：方向
P02.5：PWM
P02.6：方向
P02.7：PWM
```

继续检查驱动板后，确认板上接口形式实际为：

```text
1-A —— GND —— 1-B
2-A —— GND —— 2-B
```

因此每个电机使用两个控制输入，而不是一个方向输入加一个 PWM 输入。电机模块改为 A/B 双 PWM 控制：

```text
正向：A 输出 PWM，B 输出 0
反向：A 输出 0，B 输出 PWM
停止：A、B 都输出 0
```

随后通过单轮测试逐步确认逻辑映射。最终验证通过的映射为：

```text
逻辑左轮：P02.4 / P02.5
逻辑右轮：P02.6 / P02.7
```

之前测试中出现“第一次是右轮、第二次是左轮，且两个轮子都是反转”，说明逻辑左右分组和 A/B 极性都需要交换。修正后，单轮、双轮和正转方向均符合预期。

## 5. PID 测试流程

上车测试前先让两个驱动轮离地，避免错误输出导致小车突然移动。

KEY3 循环切换：

```text
STOP → LOW → MID → HIGH → MAX → STOP
```

KEY4 的功能为：

```text
短按：切换正转/反转
长按：目标速度清零并停止
```

正常现象包括：

- 上电后两轮不应自动启动；
- 第一个速度档位启动平稳；
- 左右轮方向一致；
- 提高目标档位后，实际转速随之提高；
- 电机不持续加速，不长期处于最大输出；
- 长按 KEY4 后两轮停止，且不会自动重新启动。

如果出现持续加速、明显抖动、PWM 饱和或方向相反，应立即停止测试。此类现象通常意味着编码器反馈方向、目标符号或 PID 参数仍需调整。

## 6. UART 调试受限后的处理

工程保留了 `PING` 和 `STATUS` 命令，但实际测试中：

- `COM9` 不存在；
- 改用 `COM14` 后可以打开串口；
- 板上能看到 `RX DATA`，说明接收链路有效；
- 电脑端没有稳定收到 `PONG`。

因此本次硬件验收没有依赖 UART 数值，而是采用 TFT 提示、按键动作和电机实际响应完成。后续仍应修复 UART TX 回传，以便观察左右目标、编码器反馈和 PID 输出。

## 7. 调试经验

这次调试最重要的经验是先隔离问题，再引入闭环：

```text
确认按键
    ↓
单轮开环
    ↓
双轮开环
    ↓
确认方向和引脚
    ↓
接入编码器
    ↓
运行双轮 PID
```

如果跳过开环验证，电机引脚接错、方向反相和编码器符号错误都会表现成“PID 不稳定”，排查成本会明显增加。
